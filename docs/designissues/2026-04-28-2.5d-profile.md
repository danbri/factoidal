# Phase 2.5d profile — F* page cache holding cottas_column directly

Issue #118, post-2.5c verification. Parliament corpus
(3.14M triples, 26 row-groups × 4 columns), `factoidal-http -p 3032`,
darwin-arm64 native binary, MacBook Air.

## Q01 — `SELECT * WHERE { ?s ?p ?o } LIMIT 1`

Timings via curl-timed HTTP GET against the running daemon:

```
Q01_cold:  6.1s
Q01_warm1: 7.3ms
Q01_warm2: 6.8ms
```

Ratio cold/warm ≈ 870×. Cold is the four-column DLBA decode of
row-group 0 (122k rows × 4 cols), warm is the F* page-cache
hit returning `cottas_column` (= `string option array`) directly,
no per-cell list cons.

Tracing confirms the F*-routed path is firing:

```
[pagecache-hot-trace] hits=N misses=N entries=78 cap=256
```

(78 entries = 26 row-groups × 3 columns visited so far; cap 256.)

## Bound-predicate baseline

```
SELECT (COUNT(*) AS ?c) WHERE { ?s a ?o }     22ms  (estimator path)
SELECT * WHERE { ?s a owl:Class } LIMIT 5    3.6s   (full walk after prune)
```

22ms COUNT confirms Tet3 + Mem5 + Aleph6 estimator path still
works. 3.6s for owl:Class LIMIT 5 is consistent with the existing
baseline (Tet3 prune lets many row-groups through because rdf:type
is densely populated; the seq filter then walks all candidates).

## Conclusion

Phase 2.5c is functionally correct. The page-cache value-shape
migration eliminates a per-cell Array.of_list allocation on every
warm cache hit; warm Q01 remains in the millisecond range. No
regression vs. the pre-2.5c baseline (which was also ~7ms warm
because the F* path was already routing through the page cache
via the `cached_decode` shim — 2.5c just removes the value-shape
adapter cost on each hit).

Phase 2.5e (retire the `search_fast` / `estimate_fast` OCaml shims
in cottas_ondisk_runtime.sh) is the architectural unwind step.
Open question: F* `cottas_ondisk_search` currently builds a fresh
`pcache_empty` per call, so a naive shim retirement loses the
process-level cross-query cache (the `Cottas_pagecache_hot.cache_ref`
that gives Q01 its 870× warm speedup). Resolution: introduce an
F* `assume val pcache_decode_global` realised in OCaml as
`Cottas_pagecache_hot.cached_decode`, so F* owns the algorithm
while OCaml provides the cross-call storage cell. That's a clean
rule-#11(c) boundary and lets the F* search path inherit the
existing warm-cache benefit without changing pure-functional F*
semantics.
